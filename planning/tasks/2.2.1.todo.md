## Notes
- **Exact Java parity verified in source:**
  - `swi` sums `mwi` in `0..12` order (`mwi[j] = (T[j] / 5.0)^1.514` if `T[j] > 0.0`, else `0.0`).
  - `a` uses `6.75e-7 * swi * swi * swi - 7.71e-5 * swi * swi + 0.01792 * swi + 0.49239`.
  - `ZPE`/`ZT` loop breaks on the first `ZT[ki] <= T < ZT[ki + 1]` for `ki in 0..23` (never indexing out of bounds because `T >= 38.0` is handled first).
  - SH `compute_with_hemisphere` preserves `(int)latDD` truncation via `(lat_dd as i32)` and the exact `(FS[i][nrow] - FS[i][nrow-1]) * ((lat_int - RS[nrow-1]) * 60.0 + ((lat_dd - lat_int) * 60.0)) / (RS[nrow] - RS[nrow-1]) * 60.0` expression (Defect #1).
  - Because `SiteInput::hemisphere()` maps `lat_dd < 0.0` to `Hemisphere::South` (Defect #7), `ForcingModel::compute_water_balance` passes negative `lat_dd` into the SH `nrow == 0` branch; having an internal `compute_with_hemisphere` helper allows both Defect #7 and Defect #1 (`5.0 <= lat < 50.0`) to be implemented verbatim and unit-tested.
  - `computeWaterBalance` updates `running_balance += precip[i]; running_balance -= mpe[i];` sequentially (not `+= (precip[i] - mpe[i])`), with SH summer order `11, 0, 1` (Dec, Jan, Feb).
