## Notes
- `SimEngine<T, F, H>` struct and `new()` are already defined in `crates/newhall-core/src/traits.rs` (`#[derive(Debug, Clone, Copy, Default)]`); `engine.rs` implements the `run` and batch methods on `crate::traits::SimEngine` without modifying `traits.rs`.
- `ClassicThermal`, `ThornthwaiteForcing`, and `ClassicHydrology` are zero-sized `Copy + Default + Send + Sync` structs implementing `ThermalModel`, `ForcingModel`, and `HydrologyStep`.
- Per Defect #2, `SiteConfig.is_metric` is stored for parity and must NOT trigger unit conversions inside `SimEngine::run`.
- `SiteOutput.water_holding_capacity` is populated directly from `input.awc_mm`, and `f64::NAN` `awc_mm` runs cleanly without panicking in `ClassicHydrology` / `ClassicThermal`.
- Bounding `T: ThermalModel + Sync, F: ForcingModel + Sync, H: HydrologyStep + Sync` unconditionally on `run_batch_soa` / `run_batch_soa_into` ensures identical API bounds with and without `--no-default-features`.
