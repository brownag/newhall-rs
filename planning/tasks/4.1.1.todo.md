# 4.1.1 -- Extend Rust FFI for per-site soil config vectors

## Notes
- **Facts discovered in Analysis:**
  - `r-pkg/src/rust/src/lib.rs` currently passes scalar `soil_air_offset: f64`, `amplitude: f64`, `has_o_horizon: bool`, `is_saturated: bool` in both `newhall_batch_rust` (L121–168) and `newhall_batch_phase4_rust` (L198–314).
  - `crates/newhall-core/src/lib.rs` exports `ForcingModel`, `HydrologyStep`, `ThermalModel`, `SimEngine`, `SoaBatchInput::site_input(&self, idx)`, `ClassicNewhall`, `StrictNewhall`, `SiteInput`, and `SiteConfig`.
  - `r-pkg/R/extendr-wrappers.R` (L9–15) already uses identical parameter names and order (`lat, lon, ..., soil_air_offset, amplitude, has_o_horizon, is_saturated, ...`) with `.Call(wrap__...)`, which in `extendr` does not encode Rust slice vs scalar types in R wrapper signatures.
- **Constraints honored:**
  - Do not touch `crates/newhall-core/`, `r-pkg/R/newhall.R`, or `r-pkg/DESCRIPTION`.
  - Preserve `run_batch_soa(&batch, &cfg)` for scalar configs (`all len == 1`).
  - Zero heap allocations in the per-site hot loop (`SiteInput` and `SiteConfig` are `Copy` and stack-allocated).
  - Early return on `n == 0` avoids out-of-bounds `[0]` indexing if a caller passes length-`0` config slices.
- **Risks:**
  - `r-pkg/R/newhall.R` (to be updated in Task `4.2.1`) still passes `isTRUE(has_o_horizon)` / `isTRUE(is_saturated)` as R logicals until `4.2.1` converts them with `as.integer(as.logical(...))`, so `devtools::test('r-pkg')` is not part of `4.1.1` targeted verification (which uses `cargo check` and `cargo clippy`).
