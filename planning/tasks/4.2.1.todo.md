# 4.2.1 -- Refactor `newhall_batch` & `newhall_batch_phase4` into S3 generics (`default`, `data.frame`, `character`)

## Goal
Refactor `newhall_batch()` and `newhall_batch_phase4()` in `r-pkg/R/newhall.R` into S3 generics (`default`, `data.frame`, and `character` for `newhall_batch`; `default` and `data.frame` for `newhall_batch_phase4`) backed by `newhall_batch_raw()` and `newhall_batch_phase4_raw()`.

## Notes
- **Facts from Analysis:**
  - `r-pkg/src/rust/src/lib.rs` (4.1.1) accepts length `1` or `n` for `soil_air_offset`, `amplitude`, `has_o_horizon` (`&[i32]`), and `is_saturated` (`&[i32]`), while Phase 4 `o_thickness`, `bulk_density`, `quartz_frac`, `porosity`, `z_wt` must have length `n` and `snow_flat` must have length `12 * n` (except when `n == 0`, which returns early).
  - `r-pkg/R/categories.R` (4.1.2) provides `.normalize_unit_system()`, `.extract_df_inputs()`, `.extract_monthly_matrix()`, `.extract_optional_col()`, and `.decode_regimes()`.
  - `r-pkg/tests/testthat/test-phase4.R` calls `newhall_batch(lat = ..., ...)` and expects integer `temperatureRegime` (`3L`), which `newhall_batch.default()` -> `newhall_batch_raw()` preserves.
  - `newhall_batch_phase4_rust` hardcodes `is_metric = true` in `lib.rs`, so `newhall_batch_phase4.data.frame()` operates in metric units.
- **Constraints honored:** Only `r-pkg/R/newhall.R` (and `planning/tasks/4.2.1.todo.md` / `planning/STATE_4.md`) will be edited; `r-pkg/src/`, `r-pkg/R/categories.R`, `r-pkg/R/raster.R`, and `crates/newhall-core/` will not be touched.
- **Risks:** Positional vector calls like `newhall_batch(lat_vec, lon_vec, ...)` bind `lat_vec` to `.data`; handled in `.default` via `if (is.null(.data)) newhall_batch_raw(...) else newhall_batch_raw(.data, ...)`.
