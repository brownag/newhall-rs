## Notes
- **Facts from Analysis:**
  - `BASICSimulationModel.java` mutates `temperature[]` in place for `5.0 -> 5.01` BEFORE running the `8.0 -> 8.01` check; using one local `let mut temp = input.temp_c;` preserves this sequence without mutating caller inputs (Defect #10).
  - In Java's `>5°C` solver (`lines 1503-1592`), if `tempUnderFive` is true, `np == 0`, and `wt > 5.0`, `skipTo890` remains `false`, falling through to `nsd = nd`, `lt5c = 360.0`.
  - In Java's consecutive-run loop (`lines 1770-1868`, `1916-2014`, `2057-2155`, `2175-2273`), `iday[n1]` is inspected one day past `i`, so an isolated 1-day match followed by non-match yields `0` when `sw == 0`, and a run continuing past the window end is preserved via `ifin`. Replicating this exact loop in one shared helper prevents subtle boundary mismatches.
  - `SiteInput::hemisphere()` derives `North` for `lat_dd >= 0.0`, `South` otherwise.
  - `DayCounters` stores `i32` casts `(int) nd[1..3]` and `(int) nsd[1..3]`, matching `NewhallResults.java:62-68`.
